# 测试：别越写越臃肿

几条轻约束，写测试、改测试时顺带遵守。

- **能用逻辑测试验证的，不写成 UI 测试。** 比如“加班算得对不对”，直接调用计算函数、传入数据、检查结果，几毫秒就跑完，挂了也一眼看出是算错了；写成 UI 测试就要启动 App、点到那一页、找到那个数字，要几十秒，界面一改还容易误报。UI 测试只留给逻辑测试测不到的事：按钮真的点得到、几个页面串起来走得通、存下的数据真的显示出来。
- **同类情况合并成一个参数化测试**，不要复制出几个只差输入的测试。
- **UI 测试不用固定等待**（`sleep`、固定等几秒），用 `waitForExistence` 或等到条件满足再继续。
- **删测试只有三种理由**：它测的功能已经删除；和另一个测试完全重复；已被更便宜的测试覆盖。PR 里写明是哪一种。“慢”本身不是删除理由，有的测试（比如 UI 流程）本来就慢。
